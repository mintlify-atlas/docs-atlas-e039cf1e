The Auditorio Estelar backend relies on a MySQL database named `teatro_proyecto`. It stores concerts, sessions, seat layout, user accounts, and reservations. Understanding the schema lets you seed data correctly and troubleshoot queries across the PHP endpoints.

## Create the database

Run the following statement before creating any tables:

```sql
CREATE DATABASE teatro_proyecto
  CHARACTER SET utf8
  COLLATE utf8_unicode_ci;

USE teatro_proyecto;
```

<Note>
  Every concert you insert should have at least two sessions in the `sesion` table. The `obtener_sesiones.php` endpoint filters for future sessions only, so a concert with no upcoming sessions will appear empty in the app.
</Note>

## Tables

### `usuario`

Stores registered app users. Passwords are stored as bcrypt hashes via PHP's `password_hash()`.

```sql
CREATE TABLE usuario (
  id_usuario  INT          NOT NULL AUTO_INCREMENT,
  nombre      VARCHAR(100) NOT NULL,
  apellido    VARCHAR(100) NOT NULL,
  email       VARCHAR(150) NOT NULL UNIQUE,
  telefono    VARCHAR(20)  NOT NULL,
  password    VARCHAR(255) NOT NULL,
  rol         VARCHAR(20)  NOT NULL DEFAULT 'cliente',
  PRIMARY KEY (id_usuario)
);
```

### `concierto`

Represents a concert shown in the app's billboard. `cartel_url` holds a URL to the poster image.

```sql
CREATE TABLE concierto (
  id_concierto INT          NOT NULL AUTO_INCREMENT,
  titulo       VARCHAR(200) NOT NULL,
  descripcion  TEXT,
  cartel_url   VARCHAR(500),
  PRIMARY KEY (id_concierto)
);
```

### `sesion`

One concert can have many sessions (dates and times). The `obtener_sesiones.php` query filters rows where `fecha > today OR (fecha = today AND hora >= now)`.

```sql
CREATE TABLE sesion (
  id_sesion    INT  NOT NULL AUTO_INCREMENT,
  id_concierto INT  NOT NULL,
  fecha        DATE NOT NULL,
  hora         TIME NOT NULL,
  PRIMARY KEY (id_sesion),
  FOREIGN KEY (id_concierto) REFERENCES concierto(id_concierto)
);
```

### `zona`

Groups seats into pricing zones. The app expects at least two zones: `"Patio"` (stalls, closest to the stage) and `"Anfiteatro"` (upper circle). These names must match exactly because `ButacasFragment` splits seats using `"Patio".equalsIgnoreCase(b.getZona())` and `"Anfiteatro".equalsIgnoreCase(b.getZona())`.

```sql
CREATE TABLE zona (
  id_zona INT           NOT NULL AUTO_INCREMENT,
  nombre  VARCHAR(100)  NOT NULL,
  precio  DECIMAL(8, 2) NOT NULL,
  PRIMARY KEY (id_zona)
);
```

### `butaca`

Individual seats. Each seat belongs to a zone and is identified by a row letter and seat number.

```sql
CREATE TABLE butaca (
  id_butaca INT NOT NULL AUTO_INCREMENT,
  fila      INT NOT NULL,
  numero    INT NOT NULL,
  id_zona   INT NOT NULL,
  PRIMARY KEY (id_butaca),
  FOREIGN KEY (id_zona) REFERENCES zona(id_zona)
);
```

### `butaca_sesion`

Junction table that tracks the availability state of each seat for a specific session. The app's `AdaptadorButacas` handles four `estado` values:

| Value | Display | Tappable |
|---|---|---|
| `DISPONIBLE` | Blue seat icon with seat number | Yes |
| `RESERVADA` | Orange icon, label `R` | No |
| `VENDIDA` | Red icon, label `X` | No |
| `BLOQUEADA` | Grey icon (30% opacity), no label | No |

```sql
CREATE TABLE butaca_sesion (
  id_butaca INT         NOT NULL,
  id_sesion INT         NOT NULL,
  estado    VARCHAR(20) NOT NULL DEFAULT 'DISPONIBLE',
  PRIMARY KEY (id_butaca, id_sesion),
  FOREIGN KEY (id_butaca) REFERENCES butaca(id_butaca),
  FOREIGN KEY (id_sesion) REFERENCES sesion(id_sesion)
);
```

When a new session is added, populate `butaca_sesion` with one row per seat so that every seat starts as `'DISPONIBLE'`.

### `reserva`

A booking header linked to a user. The `confirmar_reserva.php` endpoint inserts a row here and returns the generated `id_reserva`.

```sql
CREATE TABLE reserva (
  id_reserva INT NOT NULL AUTO_INCREMENT,
  id_usuario INT NOT NULL,
  PRIMARY KEY (id_reserva),
  FOREIGN KEY (id_usuario) REFERENCES usuario(id_usuario)
);
```

### `reserva_butaca`

Links a reservation to the specific seats and session that were booked. A single reservation can cover multiple seats.

```sql
CREATE TABLE reserva_butaca (
  id_reserva INT NOT NULL,
  id_sesion  INT NOT NULL,
  id_butaca  INT NOT NULL,
  PRIMARY KEY (id_reserva, id_sesion, id_butaca),
  FOREIGN KEY (id_reserva) REFERENCES reserva(id_reserva),
  FOREIGN KEY (id_sesion)  REFERENCES sesion(id_sesion),
  FOREIGN KEY (id_butaca)  REFERENCES butaca(id_butaca)
);
```

## Relationships

The diagram below shows how the tables connect:

- `concierto` → `sesion`: one concert has many sessions (`id_concierto` foreign key).
- `sesion` + `butaca` → `butaca_sesion`: this junction table records each seat's state per session. The `obtener_butacas_sesion.php` endpoint joins `butaca`, `zona`, and `butaca_sesion` to return seat data to the app.
- `butaca` → `zona`: each seat belongs to one zone, which determines its price.
- `usuario` → `reserva` → `reserva_butaca`: a reservation belongs to a user and references the booked seats and session.
